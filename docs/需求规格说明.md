# 轻量命令式 CI/CD 平台 —— 需求规格说明（v0.1 草案）

> 一句话定位：**自托管的「命令式部署执行器」**。项目 = 一个工作目录 + 一组 sh 命令；部署 = 点一下（或 CLI / HTTP Hook 打一下）把命令跑起来，实时看日志，拿到退出码。
>
> 不做 Jenkinsfile、不做流水线 DSL、不做 YAML 编排。**直接写 shell，点按钮就跑。**

---

## 1. 背景与目标

### 1.1 要解决的问题
- 部署脚本散落在各台机器的 crontab / 手敲 ssh / 一堆 `deploy.sh` 里，没有统一入口。
- Jenkins/GitLab CI 太重：要写 Pipeline DSL、配 Runner、概念多，小项目用不上。
- 想需要一个：**打开网页 → 选项目 → 点「执行」→ 看日志** 就完事的东西。

### 1.2 目标（Goals）
| # | 目标 |
|---|---|
| G1 | 登录后可创建项目，项目里写 sh 命令并一键执行 |
| G2 | 执行过程实时输出日志，结果可追溯（谁、何时、什么命令、成功失败） |
| G3 | 提供 Go 编写的 CLI，可在本地/CI 里用一条命令触发部署并跟随日志 |
| G4 | 每个项目暴露一个 HTTP Hook 地址，`curl` 一下即可触发部署（给 Git 平台 / 其他 CI / 脚本调用） |
| G5 | 平台默认**不代替使用者准备工具链**（git/node/go/docker 等自行安装），但提供环境自检、安装提示与**一键安装脚本**（FR-INIT-6，Linux 服务端） |

### 1.3 非目标（Non-Goals，至少 MVP 不做）
- 不做通用流水线编排引擎（无 DAG、无 stage 矩阵）
- 不做 Kubernetes Operator / 容器编排
- 不做制品仓库（不管理 jar/镜像的存储与版本）
- 不做代码托管、不做代码评审
- 不做堡垒机 / 细粒度命令审计到参数级别的高安全场景（定位是**内网自用的效率工具**）

### 1.4 典型使用场景
1. **个人开发者**：一台云服务器，网页上点「执行」跑 `git pull && go build && systemctl restart app`。
2. **小团队**：每人有自己的项目，管理员统一账号，执行记录可查。
3. **CI 集成**：GitHub Actions / 本地脚本 `curl -X POST .../hooks/xxx` 触发服务器部署。
4. **开发者本地**：`deploy run my-app -f` 触发并实时跟随日志。

### 1.5 已确认的关键决策（v0.1 定稿）

| # | 决策 | 结论 | 对设计的影响 |
|---|---|---|---|
| D1 | 命令执行位置 | **Server 所在机器**（本机执行） | MVP 不写 Agent；数据模型保留 `runners` 表与 `run.runner_id` 字段占位，P2 再落地 |
| D2 | 是否托管代码拉取 | **两种都要，项目级开关** | 项目新增 `use_git` 开关；执行流程增加「Git 准备阶段」；需处理凭据、失败中止、Git 变量注入 |
| D3 | 用户体系 | **多用户 + `admin`/`user` 两种角色** | 用户管理、API Token、按 owner 判定权限进入 P0/P1 |
| D4 | 存储与交付 | **SQLite + 单二进制（前端 `embed`）+ Dockerfile** | 用纯 Go SQLite 驱动免 CGO；构建产物一个可执行文件；额外提供 Docker 镜像 |
| D5 | 前端 | **沿用现有 Ant Design Pro 模板裁剪** | 先做减法（删示例页/删 mock/关 MOCK），再写 6 个业务页 |
| D6 | 工具链 | 默认不主动安装，只做环境自检与引导；另提供**一键安装脚本**（页面上可触发，仅 Linux 服务端） | 「环境自检」进 P0；文档必须写清系统依赖 |

> D2 是本轮唯一显著增加复杂度的决策，展开见 §5.4.1「Git 准备阶段」。

## 2. 系统组成

```
┌──────────────────────────────┐
│  Web 前端 (React + antd Pro)  │
└──────────────┬───────────────┘
               │ HTTP / WebSocket
┌──────────────▼───────────────┐        ┌─────────────────────────┐
│  deploy-server (Go)          │◄───────┤  deploy-cli (Go)        │
│  · REST API                  │  HTTP  │  · login / run / logs   │
│  · WebSocket 日志推送         │  Hook  │  · 环境自检 doctor       │
│  · 执行引擎 (os/exec)         │        └─────────────────────────┘
│  · SQLite + 日志文件          │
│  · 前端静态资源 (embed)        │◄─────── curl / Git Webhook / 其他 CI
└──────────────┬───────────────┘
               │ 在 **Server 所在机器** 上执行 shell
        ┌──────▼───────┐
        │  目标工作目录  │  /opt/workspaces/<project>
        └──────────────┘
```

三个交付物：
1. **deploy-server**：Go 后端 + 内置前端静态资源，单二进制。
2. **deploy-server-ui**：React 前端（基于现有 Ant Design Pro 模板裁剪）。
3. **deploy-cli**：Go 命令行客户端。

## 3. 角色与权限

| 角色 | 说明 | 权限 |
|---|---|---|
| 超级管理员 `admin` | 初始化时创建 | 全部：用户管理、系统设置、查看/操作所有项目 |
| 普通用户 `user` | 管理员创建或开放注册 | 自己项目的增删改查与执行；他人项目只读（可配置） |
| 服务账号 `service` | 给 CI/Hook 用的无人值守账号 | 仅能通过 API Token / Hook Token 触发指定项目 |

权限模型：`角色(role)` + `资源归属(owner_id)`，MVP 不做 RBAC 表，两个角色足够。

## 4. 核心概念模型

| 概念 | 说明 |
|---|---|
| **Project 项目** | 部署单元。含：名称、唯一 Key、工作目录、环境变量、命令列表、超时、通知配置 |
| **Command 命令** | 项目下的一条 sh 脚本，有名称、顺序、启停、失败策略 |
| **Run 运行记录** | 一次执行的实例。build number、触发方式、状态、耗时、日志、退出码 |
| **RunStep 步骤记录** | Run 中每条 Command 的执行结果（状态、耗时、退出码） |
| **Hook Token 触发令牌** | 绑定项目的密钥，用于 `POST /hooks/{token}` 触发 |
| **API Token 接口令牌** | 绑定用户的密钥，CLI / 第三方调用 REST API 用 |
| **Runner 执行器** | 执行命令的载体。MVP = server 本机；P2 = 远程 Agent |

## 5. 功能需求

### 5.1 认证与账号（FR-AUTH）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-AUTH-1 | 用户名 + 密码登录，成功后签发 JWT（Access Token），返回用户信息 | P0 |
| FR-AUTH-2 | Token 有有效期；支持刷新或重新登录；前端 401 自动跳登录页 | P0 |
| FR-AUTH-3 | 首次启动自动创建管理员（默认 `admin`，密码随机生成打印到日志 / 或首次访问引导设置），并**强制首次改密** | P0 |
| FR-AUTH-4 | 修改自己的密码（校验旧密码） | P0 |
| FR-AUTH-5 | 退出登录（前端清理本地 Token）；服务端可选 Token 黑名单 | P1 |
| FR-AUTH-6 | 管理员：用户列表/新建/编辑/禁用/删除/重置密码/改角色 | P1 |
| FR-AUTH-7 | 登录失败次数限制（如 5 次锁 10 分钟），记录来源 IP | P1 |
| FR-AUTH-8 | 个人 API Token 管理：创建（明文仅显示一次）、备注、复制、删除 | P1 |
| FR-AUTH-9 | 关闭公开注册（默认关闭）；如需注册须邀请码（P3） | P1 |
| FR-AUTH-10 | 记住我 / 长期会话（可选） | P2 |

密码存储：bcrypt（cost ≥ 10）或 argon2id。API/Hook Token 只存哈希，前缀明文便于识别。

### 5.4 执行引擎（FR-RUN）★核心

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-RUN-1 | 触发方式：① Web 点击「执行」 ② REST API ③ CLI ④ HTTP Hook ⑤ Git Webhook(P2) ⑥ 定时 Cron(P2) | P0(1-4) |
| FR-RUN-2 | 每次执行生成 Run 记录：自增 build number（项目内递增）、项目、触发人、触发方式、开始/结束时间、耗时、状态、退出码 | P0 |
| FR-RUN-3 | 状态机：`queued` → `running` → `success` / `failed` / `canceled` / `timeout` / `error`（启动失败） | P0 |
| FR-RUN-4 | 执行 shell：Unix 用 `bash -lc`（回退 `sh -c`），Windows 用 `pwsh -Command`（回退 `cmd /c`）；cwd = 项目工作目录 | P0 |
| FR-RUN-5 | 环境变量 = 系统环境 + 项目 env + Secret env + 内置变量（后者覆盖前者，冲突时记录警告） | P0 |
| FR-RUN-6 | **实时日志**：stdout/stderr 合并流式采集，按行（或按字节块）推送到 WebSocket 订阅者 | P0 |
| FR-RUN-7 | 日志持久化：写文件 `${DATA_DIR}/logs/{project}/{run_id}.log`（含 ANSI 转义），DB 存元信息与索引 | P0 |
| FR-RUN-8 | 历史日志查询：全量拉取 / 分页 / 按 offset 增量拉取（断线重连后补齐） | P0 |
| FR-RUN-9 | 取消运行：终止整个**进程树**（Unix 用 `Setpgid` + `kill(-pgid)`；Windows 用 Job Object 或 `taskkill /T /F`） | P0 |
| FR-RUN-10 | 超时控制：项目级与单命令级，超时后按取消逻辑处理并标记 `timeout` | P0 |
| FR-RUN-11 | 并发控制：同项目按 `concurrency` 策略处理；全局最大并发数（系统设置），超出进入 `queued` | P0 |
| FR-RUN-12 | 日志打码：Secret 变量的值在写入日志/推送前替换为 `***` | P0 |
| FR-RUN-13 | 退出码与状态映射：全部命令成功 = success；任一 `abort` 命令失败 = failed | P0 |
| FR-RUN-14 | 重新执行（Rerun）：以相同项目与参数再触发一次 | P1 |
| FR-RUN-15 | 手动传参：触发时可传 `-e KEY=VAL` 覆盖变量（需项目开启「允许覆盖」） | P1 |
| FR-RUN-16 | 运行列表：全局与项目维度，按状态/项目/时间筛选 | P0 |
| FR-RUN-17 | 服务重启后：`running` 状态的僵尸运行标记为 `error`（或按策略续跑，MVP 直接标记中断） | P0 |
| FR-RUN-18 | 日志保留策略：默认保留 30 天 / 每项目最多 N 条，定时清理 | P1 |
| FR-RUN-19 | **依赖构建流水线**：触发时可选「含依赖构建」；按拓扑序（深度优先、依赖在前、同一项目只构建一次）先构建依赖的构建项目，全部成功后再执行本项目 | P0 |
| FR-RUN-20 | 依赖构建失败即中止：后续依赖与目标项目都不执行；目标 Run 落成 `failed`（依赖被取消则为 `canceled`），`errorMsg` 与日志写明是哪个依赖、哪条 Run 失败 | P0 |
| FR-RUN-21 | 依赖用同一个分支 / Tag，但不继承触发时传入的 env 覆盖；依赖项目自身仍完整执行其全部命令并各自产生 build number | P0 |
| FR-RUN-22 | 一次带依赖的触发产生的多条 Run 用 `pipelineId` 关联，运行详情页展示「前置构建」列表与状态并可跳转 | P1 |
| FR-RUN-23 | 取消流水线中的任意一条 Run 会连带取消同一条流水线里还在跑 / 排队的其它 Run | P1 |
| FR-RUN-19 | 下载日志文件（txt） | P1 |
| FR-RUN-20 | 执行期间服务端优雅关闭：等待或标记中断，不丢日志 | P1 |

#### 5.4.1 Git 准备阶段（D2：项目级开关）

执行流程被划分为两个阶段：

```
Run 开始
  ├── [可选] Phase 1: Prepare —— 仅当 project.use_git = true
  │     · 目录不存在 → git clone <url> -b <branch> [--depth N] [--recurse-submodules] <workdir>
  │     · 目录已存在且是 git 仓库 → git fetch && git checkout <branch> && git reset --hard origin/<branch>
  │     · 目录已存在但不是 git 仓库 → 默认报错中止（避免误覆盖），可由项目开关允许「清空后重新 clone」
  │     · 可选 git clean -fdx（默认关闭，需显式开启并二次确认）
  │     · 采集 commit 信息注入内置变量
  └── Phase 2: Commands —— 按顺序执行用户命令
```

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-GIT-1 | `use_git=false`（默认）时执行流程与普通命令完全一致，零额外开销 | P0 |
| FR-GIT-2 | `use_git=true` 时先执行 Prepare 阶段，**Prepare 失败则不执行任何用户命令**，Run 状态为 `failed` 并标记失败阶段为 `prepare` | P1 |
| FR-GIT-3 | 凭据注入方式：HTTPS 用 `GIT_ASKPASS` 或临时 credential helper（**不要把 token 拼进 URL**，避免出现在日志与 `git remote -v` 中）；SSH 用临时 key 文件 + `GIT_SSH_COMMAND` 指定 | P1 |
| FR-GIT-4 | 内置 Git 变量：`GIT_COMMIT`、`GIT_COMMIT_SHORT`、`GIT_BRANCH`、`GIT_TAG`（最近 tag）、`GIT_AUTHOR`、`GIT_MESSAGE`、`GIT_DIRTY`（是否有本地改动） | P1 |
| FR-GIT-5 | Prepare 阶段日志与用户命令日志写入同一日志流，但以 `=== [prepare] ===` 分隔并支持在 UI 上折叠 | P1 |
| FR-GIT-6 | 触发时可用 `branch` 参数覆盖项目默认分支（Hook / CLI / Web 均支持），并记录到 Run 上 | P1 |
| FR-GIT-7 | clone/pull 超时独立控制（默认 10 分钟），避免网络卡死占用并发额度 | P1 |
| FR-GIT-8 | 支持 Tag 与任意 Commit SHA（`git checkout <ref>`，`GIT_BRANCH` 此时记录 ref） | P2 |
| FR-GIT-9 | **同一项目串行执行**（`concurrency=queue`）时，Prepare 与 Commands 在同一把项目锁内，防止两个 Run 同时 checkout 造成工作区错乱 | P1 |
| FR-GIT-10 | 允许并行（`concurrency=allow`）时给出明确警告：多个 Run 共享同一工作目录会互相踩踏，建议配合 `git_subdir` 或改为串行 | P2 |

> 实现建议：**不要用 `exec.Command("git clone ...")` 拼接 shell 字符串**，用参数数组调用 `git`，避免 URL/分支里的特殊字符引发注入。

### 5.5 HTTP Hook 触发（FR-HOOK）★用户明确要求

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-HOOK-1 | 每个项目可生成 1..N 个 Hook Token，可命名、可重置、可删除、可设过期时间 | P0 |
| FR-HOOK-2 | 触发端点：`POST /api/v1/hooks/{token}`，token 也可放 Header `X-Deploy-Token` | P0 |
| FR-HOOK-3 | 请求体（可选 JSON）：`{"branch":"main","env":{"K":"V"},"command_ids":[1,2],"async":true}` | P0 |
| FR-HOOK-4 | 响应：默认异步，返回 `202 {run_id, build_number, status_url, log_url}`；带 `?wait=true` 时同步等待结束并返回结果摘要（适合 CI 卡住等结果） | P0 |
| FR-HOOK-5 | 无需登录态，仅凭 Token；Token 校验失败返回 401，项目归档/禁用返回 403 | P0 |
| FR-HOOK-6 | 调用方信息记录：来源 IP、User-Agent 写入 Run 的触发信息 | P0 |
| FR-HOOK-7 | 限流：单 Token 每分钟 N 次（默认 60），防误刷 | P1 |
| FR-HOOK-8 | IP 白名单（可选，CIDR） | P2 |
| FR-HOOK-9 | Git Webhook 兼容：识别 GitHub/GitLab/Gitee 的 push payload，校验签名（`X-Hub-Signature-256` / `X-Gitlab-Token`），支持「仅特定分支触发」 | P2 |
| FR-HOOK-10 | 触发时支持 `X-Idempotency-Key`，相同 key 在窗口期内只触发一次 | P3 |

示例：
```bash
curl -X POST https://deploy.example.com/api/v1/hooks/HK_xxxxxxxx \
     -H 'Content-Type: application/json' \
     -d '{"branch":"main","env":{"TAG":"v1.2.3"},"async":false}'
```

### 5.6 客户端 CLI（FR-CLI）★用户明确要求

技术：Go + `spf13/cobra`，单二进制，交叉编译（linux/darwin/windows × amd64/arm64）。

配置文件 `~/.deploy/config.yaml`（Windows：`%USERPROFILE%\.deploy\config.yaml`），权限 0600：

```yaml

  default:
    server: https://deploy.example.com

    user: admin
```

命令设计：

| 命令 | 说明 | 优先级 |
|---|---|---|
| `deploy login [-s URL] [-u USER]` | 交互输入密码登录，保存 Token；支持 `--token` 直接写入 | P0 |
| `deploy logout` | 清除本地 Token | P0 |
| `deploy whoami` | 显示当前登录用户与服务器 | P1 |
| `deploy project list` | 列出可见项目（表格输出） | P0 |

| `deploy run <key>` | 触发执行。`-f/--follow` 跟随日志，`-e K=V` 传参，`--branch` 指定分支，`--wait` 等待结果 | P0 |
| `deploy logs <run_id> [-f]` | 查看/跟随指定运行日志 | P0 |

| `deploy version` / `--version` | 版本信息 | P0 |

CLI 行为约定：
- 全局参数：`--server`、`--token`、`--json`、`--no-color`、`--verbose`
- 环境变量兜底：`DEPLOY_SERVER`、`DEPLOY_TOKEN`（便于 CI 中免配置文件）
- **退出码语义**：`0` 成功；`1` 部署失败；`2` 用法错误；`3` 鉴权失败；`4` 网络/服务不可用（方便脚本判断）
- `Ctrl+C` 默认只**断开日志跟随**，不取消运行；`deploy run --cancel-on-interrupt` 才取消
- 日志彩色输出保留 ANSI；非 TTY 或 `--no-color` 时剥离 ANSI
- 断线自动重连并补齐日志（按 offset 续拉）
- 交互式操作提供提示；所有交互命令都必须有非交互等价参数

### 5.8 环境自检与首次使用引导（FR-INIT）★对应用户「工具链第一次配置」的想法

**前提澄清（v0.2 修订）**：平台默认**不主动安装**任何工具链（git / go / node / docker / nginx…），使用者在部署服务器上自行准备；平台做三件事：

1. 环境自检：报告有没有、什么版本、路径，缺失项给出**安装提示文案**；
2. **一键安装**（新增，见 FR-INIT-6）：把常用构建工具链（JDK、Maven、nvm/Node/pnpm、Go、Rust、gcc/make）的安装脚本内嵌进二进制，在页面上点一下就在服务端装好——安装过程是**一次普通 Run**，所以实时日志、取消、重跑、下载全部复用；
3. 首次使用引导向导。

设计取舍：脚本只在 Linux 上执行（依赖 bash 与 apt/dnf），且默认走国内镜像；只有 admin 能触发；提供 `--dry-run` 预演；幂等（已装组件跳过）；写入 `/etc/profile.d` 而不是改 apt 源，也不覆盖已有的 `~/.m2/settings.xml`、`~/.cargo/config.toml`。

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-INIT-1 | 首次启动引导向导（Web）：① 设置管理员密码 → ② 设置工作根目录（默认 `./workspaces`）→ ③ 环境自检 → ④ 创建第一个项目 | P0 |
| FR-INIT-2 | 环境自检 `GET /api/v1/system/doctor`：检测服务端 OS/Arch、可用 shell、工作根目录是否可写、git/go/node/docker/npm/pnpm 等是否存在及版本 | P0 |
| FR-INIT-3 | 自检结果展示为「✔ 已就绪 / ✘ 未找到」清单，未找到的给出**安装提示文案** | P0 |
| FR-INIT-4 | 配置项以配置文件 / 环境变量为准，Web 上可覆盖部分可热改配置（并发上限、日志保留） | P1 |
| FR-INIT-5 | 提供文档：服务端安装步骤（二进制 + systemd / Docker）、所需系统依赖说明 | P0 |
| FR-INIT-6 | **工具链一键安装**：`GET /system/toolchains` 列出组件与当前状态；`POST /system/toolchains/install` 触发安装（仅 admin，支持勾选/全部缺失/预演）；安装以普通 Run 执行，跳转运行详情看实时日志；`GET /system/toolchains/script` 可下载脚本手动执行 | P0 |
| FR-INIT-7 | 安装脚本幂等：已安装组件默认跳过（`--force` 覆盖）；单个组件失败不影响其它组件，最后汇总并以退出码反映 | P0 |
| FR-INIT-8 | 安装脚本只做「保守修改」：写 `/usr/local`、`/etc/profile.d`，不碰 apt 源；已有 `settings.xml` / `cargo config.toml` 不覆盖 | P1 |

### 5.9 通知（FR-NOTIFY，P1）

- 渠道：自定义 Webhook（通用）、飞书、钉钉、企业微信、邮件(SMTP)
- 触发条件：成功 / 失败 / 全部；可只在状态变化时通知
- 内容：项目名、build number、状态、耗时、触发人、日志尾部 N 行、运行详情链接
- 项目级覆盖全局配置

### 5.10 审计与操作日志（FR-AUDIT，P2）

记录：登录/登出、项目增删改、命令修改、执行触发、取消执行、用户管理、系统设置变更。字段：时间、操作人、IP、动作、对象、变更摘要。

### 5.11 凭据管理（FR-CRED，因 D2 引入）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-CRED-1 | 凭据类型：`https_token`（用户名 + Token/密码）、`ssh_key`（私钥 + 可选 passphrase） | P1 |
| FR-CRED-2 | 凭据归属用户或全局（admin 维护）；项目只能引用自己有权使用的凭据 | P1 |
| FR-CRED-3 | 私密内容用 AES-GCM 加密存储，密钥来自 `DEPLOY_SECRET_KEY` 配置或启动时生成的 `.key` 文件（权限 0600） | P1 |
| FR-CRED-4 | 前端只展示凭据名称与类型，密文永不出参；写入日志时统一打码 | P1 |
| FR-CRED-5 | 凭据被项目引用时禁止删除（或提示引用方） | P2 |
| FR-CRED-6 | 凭据使用情况可查：哪些项目在用、最后使用时间 | P2 |

> 若 MVP 阶段想进一步压缩范围：D2 的 Git 准备阶段可以先只支持**公开仓库 + HTTPS 凭据**，SSH Key 放到 P2。这样能省掉临时 key 文件、`known_hosts`、passphrase 处理等一堆边角。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| **部署形态** | ① **主交付：单二进制（前端 `embed` 进去）+ SQLite**，解压即用，无 CGO 依赖；② 同时提供 Dockerfile / docker-compose；③ MySQL/PostgreSQL 作为 P3 可选（GORM 已支持，不写方言特定 SQL 即可平滑切换） |

| **性能** | 单机 ≥ 200 个项目、≥ 50 并发运行；日志流式处理不驻留内存；单条运行日志支持 ≥ 100MB |

| **平台安全** | 本平台本质是「远程命令执行」，必须：强制登录、Token 鉴权、操作审计、默认不开放注册、默认 CORS 白名单；生产部署文档强制要求 HTTPS（反代） |

| **可观测** | 结构化日志（slog/zap）、`/healthz`、`/readyz`；可选 `/metrics`（Prometheus） |
| **可维护性** | 分层清晰（handler → service → repository）、接口有 OpenAPI 文档、单元测试覆盖核心逻辑（执行引擎、变量渲染、权限） |
| **国际化** | 中文优先，文案集中在 i18n 文件（预留英文） |
| **浏览器兼容** | Chrome / Edge 最新两个大版本 |

## 7. 数据模型（初稿）

```

api_tokens       (id, user_id, name, token_hash, prefix, expires_at, last_used_at, created_at)

                  git_clean, git_submodule, created_at, updated_at)
                  -- kind: app|lib；dependencies_json: 依赖的构建项目 key 数组（JSON 文本）
project_commands (id, project_id, name, script, sort_order, enabled, fail_strategy,
                  workdir_override, timeout_sec, shell_override, created_at, updated_at)

                  -- pipeline_id 相同的一组 Run 属于同一次「含依赖构建」触发；
                  -- pipeline_role: main|dependency，pipeline_order: 依赖从 1 开始，主项目为 0
```

> SQLite 注意事项：开启 `PRAGMA journal_mode=WAL` 与 `busy_timeout`，否则并发写（多个 Run 同时更新状态 + 日志 offset）容易出现 `database is locked`。写入 run 状态与步骤进度建议走单写协程/串行队列。

## 13. 风险与注意事项

| 风险 | 说明 | 应对 |
|---|---|---|
| **任意命令执行 = 高危** | 平台被攻破等于服务器被拿下 | 强制登录、默认绑定 127.0.0.1 或要求反代加 HTTPS、审计日志、Token 可撤销、文档明示风险 |
| 进程树残留 | Windows/Unix 终止语义不同，子进程可能变孤儿 | 平台特定实现（pgid / Job Object）+ 测试用例覆盖 |
| 日志量爆炸 | 长时间运行的命令输出巨大 | 流式写盘 + 订阅者背压 + 单条日志大小上限（超出截断并提示） |
| 前端模板冗余 | 当前模板含大量示例页与 mock，直接改易踩坑 | 先做「减法」：删页面 + 删 mock + 关 MOCK，再开发业务页 |
| WebSocket 鉴权 | 浏览器 WS 无法自定义 Header | 用一次性 ticket 或 query token，避免长期 Token 进 URL 日志 |
| 中文路径/编码 | Windows 下 shell 与编码差异 | 明确 UTF-8，Windows 优先 pwsh；文档标注支持度 |
| 定时任务与重启 | 服务重启后运行中任务处理 | MVP 标记为中断；P2 做恢复或重跑提示 |
| **Git 双模式引入的状态污染** | 平台拉代码后，用户命令里的 `git pull`、本地改动、脏工作区可能与 Prepare 阶段打架；并行 Run 会互相踩踏同一目录 | Prepare 用 `fetch + reset --hard` 保证确定性；同项目默认串行并共用一把锁；`git_clean` 默认关闭且需二次确认；允许并行时给出显式警告 |
| **凭据泄露** | HTTPS Token 若拼进 URL 会留在日志、`.git/config`、进程列表里 | 用 credential helper / `GIT_ASKPASS` 注入，绝不拼 URL；日志统一打码；`git remote -v` 不落明文 |
| SQLite 并发写 | 多 Run 同时更新状态与日志 offset 易 `database is locked` | 开启 WAL + `busy_timeout`；状态与进度写入走单写协程串行化 |
| 多用户下的越权 | 项目只读用户可能通过接口拿到 Secret 或执行 | 所有项目接口统一走「owner 校验中间件」；env 列表按角色过滤；执行前再次校验 |
